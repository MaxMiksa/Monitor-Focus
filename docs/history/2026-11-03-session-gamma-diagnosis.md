# 后台远程会话启动导致色温丢失：实机诊断

日期：2026-11-03，时间均为 Asia/Shanghai。仅排查，未修改生产代码或重新部署。

## 结论

复现确认：GenshinLauncher 为 BetterGI 建立 BGIDaily 的后台 RDP 会话时，前台 AOC 外屏 Gamma 从已应用的暖色重置为原色。Monitors Focus 保留 3200K 目标和成功缓存，不读取外部变化，相同目标不会重新应用，形成界面数值与实际颜色不一致。改变色温目标能立即恢复，无需结束游戏。

本次不是显示器绑定错误或硬件亮度被重置：前台核心始终为会话 1 的 PID 26112，设备映射保持 DISPLAY2/AOC 与 DISPLAY1/BOE；外屏硬件背光始终为 10，内屏 WMI 背光始终为 45。暖色撤掉同时伴随用户感知的变亮，不能把该观感变化等同于硬件背光变化。内屏本次未启用 Gamma 调色。

已定位触发阶段和应用恢复缺口；没有跟踪究竟由 Windows、驱动或会话初始化中的哪个进程执行了 Gamma 重置，不归责于某个具体系统组件。用户最初描述的“直到游戏结束才可调整”未在本次重现，用户复验已修正为启动时突变、手动调整可生效。

## 代码原因

- `ControlCenterContext.Tick`：`d.LastRequest == target` 时直接跳过设备工作，没有核对当前 Gamma。
- `ControlledDisplay.Apply`：`_lastKelvin == target.Kelvin` 时跳过色温应用，因此仅改变亮度也不能保证恢复被重置的暖色。
- `GammaColorDevice.Apply` 本身允许当前表回到保存的 baseline 后重新应用，但以上两层缓存让它在目标不变时没有执行机会。
- 当前显示事件处理不覆盖所有外部 Gamma 重置；此次完整采样没有出现持续重新检测或控制对象更换。

修复方向：在会话/显示环境变化后或低频检查中验证已拥有的颜色状态；确认退回自己的原色基线时，允许重新应用原目标，绕过上述缓存。遇到未知第三方颜色表时继续遵守不抢写约定。须区分目标值与实际应用状态，避免界面无提示地显示失效目标。

诊断只发送了一次同值色温、一次 3300K 和恢复夜间场景请求；未修改持久配置、未操作后台游戏。临时采集脚本停止后清理，保留原始证据。
